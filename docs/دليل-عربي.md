# دليل Violet Finance بالعربي

دليل مختصر لإلك ولأي حدا رح يشتغل على النظام بعدين. التفاصيل الكاملة بالإنكليزي موجودة بباقي ملفات `docs/`.

## 1. شو في جوّا النظام

- **الفورمات (PTR، JAR، Advance…)** محفوظة كـ JSON بقاعدة البيانات، وبتتعدّل من Form builder. يعني تعديل فورم ما بيحتاج مبرمج.
- **الحسابات بتصير على السيرفر بس.** الشاشة بتبعت البيانات والسيرفر بيرجّع النتيجة، لهيك الطباعة والتقارير ما بتختلف أبداً عن الشاشة.
- **الأرقام T2600001** بتمشي ورا بعض. الرقم يلي بينحذف ما بيرجع بينعطى لحدا.
- **أسعار الصرف** بتنكتب متل ما بيقولها السوق (1 EUR = 1.16 USD، و1 USD = 122 SYP)، والنظام بيخزّنها على طريقة QuickBooks (كم دولار بالوحدة).
- **أرقام الموازنة** صارت تنقرأ من جدول `spend_lines`، ويلي بيتعبّى لحالو كل ما ينحفظ فورم أو تعدّلو الخزينة أو ينلغى.

## 2. التحديث على السيرفر

```
sudo violet update live      # تحديث مباشر
sudo violet log live         # آخر الأخطاء (إذا طلع خطأ 500)
sudo violet rollback live    # ترجيع النسخة السابقة (كود + قاعدة بيانات)
sudo violet backup live      # نسخة احتياطية هلق
```

صار في حماية جديدة: بعد كل تحديث الأداة بتفتح صفحة الدخول. إذا ردّت بخطأ 500، بترجّع النسخة الاحتياطية لحالها وبتطبعلك سطر الخطأ. ابعتلي هالسطر.

**الطريقة الأسلم:** `sudo violet sync-test` وبعدها `sudo violet update test`. جرّب على موقع التجربة، وإذا كلشي تمام: `sudo violet promote`.

**نسخة احتياطية يومية:** بتنضاف هيك لـ crontab تبع root:
`30 2 * * * /usr/local/bin/violet backup live >> /var/log/violet-backup.log 2>&1`
وإذا حطيت بـ `/etc/violet-deploy.conf` سطر `OFFSITE=...` (سيرفر تاني أو مجلد مركّب)، كل نسخة بتنسخ كمان لبرّا السيرفر.

## 3. التحقق بخطوتين (2FA)

- المدير وكل حدا عندو صلاحية حساسة (مستخدمين، أدوار، إعدادات، أرقام، خزينة، مدفوعات مستلمة، Form builder) لازم يفعّلها. النظام بيحوّلو لصفحة حسابو لحتى يفعّلها.
- التفعيل: حسابي ← Two-factor ← امسح الـ QR بتطبيق Google Authenticator أو Microsoft Authenticator ← اكتب الكود ← احفظ أكواد الاسترجاع الثمانية.
- إذا حدا ضيّع موبايلو: صفحة المستخدم ← Reset two-factor، أو من السيرفر `php artisan violet:2fa-reset email`.
- فيك توقف الإلزام من الإعدادات (Settings ← Security)، بس ما بنصح فيه.

## 4. سجل التدقيق (Audit trail)

أي شي بيغيّر مصاري أو صلاحيات بينسجل: حذف، فتح فورم مقفول، تعديل قيمة الدفع، تصحيح مدفوعات مستلمة، أسعار صرف، مستخدمين وأدوار.
السجل ما بينعدّل ولا بينحذف من النظام، وكل سطر مختوم بالسطر يلي قبلو. زر **Check the chain** بيكشف إذا حدا لعب بقاعدة البيانات مباشرة.

## 5. أسعار الصرف المؤرخة

الإدارة ← Exchange rates. فيك تنسخ من Excel أسطر بالشكل: التاريخ، رمز العملة، السعر.
المدفوعات المستلمة والمصاريف يلي ما إلها سعر خاص بتاخد سعر يومها. آخر سعر بيصير كمان سعر اليوم.

## 6. الاختبارات: كيف بتشتغل وكيف بتكتب واحد

**شو يعني اختبار؟** كود صغير بيشغّل جزء من النظام وبيتأكد إنو النتيجة صح. مثلاً: "فاتورة 1500 يورو بسعر 1.16 لازم تطلع 1740 دولار". إذا حدا غيّر شي وخرّب الحساب، الاختبار بيصير أحمر قبل ما توصل الغلطة للسيرفر.

**التشغيل** (على جهاز فيه PHP وإنترنت، أو بأي سيرفر تجريبي):

```
tests/run.sh                     # كل الاختبارات (تقريباً 15 ثانية)
tests/run.sh --filter PtrRates   # اختبارات أسعار PTR بس
```

كل اختبار بيبلّش بقاعدة بيانات فاضية بالذاكرة. ما بيلمس الداتا الحقيقية أبداً.

**على GitHub:** كل ما ينرفع كود، الاختبارات بتشتغل لحالها. بصفحة المستودع، جنب آخر commit:
- ✅ أخضر: فيك تحدّث السيرفر.
- ❌ أحمر: لا تحدّث. افتح الإشارة وشوف أي اختبار فشل.

**كتابة اختبار جديد:** كل اختبار إلو تلات خطوات (جهّز، نفّذ، تأكّد):

```php
public function test_dollar_invoice_paid_in_syrian_pounds(): void
{
    // جهّز: فاتورة 1622 دولار، دفع بالليرة السورية بسعر 122
    $d = ['invoice_currency_id' => $this->cur('USD')->id, 'payment_currency_id' => $this->cur('SYP')->id,
          'inv_per_usd' => 1, 'pay_per_usd' => 122, 'lines' => [['invoice_amount' => 1622]]];
    // نفّذ: احسب الفورم
    $out = FormRegistry::get('ptr')->compute($d + ['date' => '2026-11-01']);
    // تأكّد: لازم يطلع 197,884
    $this->assertEqualsWithDelta(197884, $out['lines'][0]['expected_amount'], 0.001);
}
```

**القاعدة الذهبية:** كل غلطة بتلاقيها بتصير اختبار. بتكتب الاختبار يلي بيفشل بسبب الغلطة، بعدين بتصلّح، وبيصير أخضر وبيضل حارس إنو الغلطة ما ترجع.

## 7. مطابقة QuickBooks

القائمة: Control ← QuickBooks check.
1. بـ QuickBooks: Reports ← Transaction List by Date ← اختار الشهر ← Export to Excel.
2. إذا بتشتغل بأكتر من عملة، ضيف عمودَي Foreign Amount وCurrency من Customize.
3. ارفع الملف. النظام بيطابق كل معاملة برقمها (T2600123)، لأنو رقم المعاملة بينكتب بخانة No. بـ QuickBooks من ملف الرفع.

كل فورم إلو نوع معاملة بـ QuickBooks: الـ PTR والـ JAR بيصيروا **Bill**، والـ Journal بيصير **Journal Entry** أو **Payment**. إذا معاملة انسجلت بنوع غلط، بتطلع بقسم لحالها.

النتيجة بتطلع بأقسام: مطابق، المبلغ مختلف، مو موجود بـ QuickBooks، ملغى بالنظام وموجود بـ QuickBooks، رقم مو معروف، مكرّر بـ QuickBooks.
كل مطابقة بتنحفظ وبتنكتب بسجل التدقيق، وفيك تنزّلها Excel.

## 8. الطباعة

صارت الطباعة على Google Chrome بدل wkhtmltopdf يلي توقف تطويرو. لازم تنصّبو مرة وحدة على السيرفر:
`sudo bash /opt/violet-src/deploy/install-server-tools.sh`
وبعدها تتأكد بأمر `violet:pdf-check`. إذا Chrome مو منصّب، النظام بيضل يطبع بـ wkhtmltopdf متل قبل.

## 9. أوامر مفيدة على السيرفر

| الأمر | شو بيعمل |
|---|---|
| `php artisan violet:expenses-rebuild` | بيعيد بناء أرقام الصرف لكل الفورمات النهائية |
| `php artisan violet:audit-verify` | بيفحص سلسلة سجل التدقيق |
| `php artisan violet:2fa-reset email` | بيوقف التحقق بخطوتين لمستخدم |
| `php artisan violet:pdf-check` | بيقلك أي محرك طباعة شغّال، وبيطبع صفحة تجربة |
